# Привязки к памяти игры

Сеть, лобби, гонки, зачёт и карьера работают без единого адреса. Чтобы мод видел
машину игрока и трафик, нужна таблица адресов **под вашу сборку** `speed2.exe`.

## Что уже проверено

`coop-probe` разбирает PE и проверяет документированные якоря (из README мода
Crashing Foreign Cars, Chrystian Farias). На проверенной сборке:

```
sha256 bc34932b36bb19194000690ec26edf964176856c31fb0978e01e61ee814eee9d
10/10 anchors resolved, pattern scan Player::ClearZone -> 0x5FFE70
```

| Якорь | VA | Зачем моду |
|---|---|---|
| `Player::ClearZone` | `0x5FFE70` | смена зоны/загрузка; хорошая точка «игра перешла в другой мир» |
| `MenuScreen::BaseNotify` | `0x55B5C0` | события меню; здесь видно завершение карьерного события |
| `BuyCarPart` | `0x5289F0` | покупка в магазине — точка синхронизации карьеры |
| `InstallPart` | `0x55C230` | установка детали |
| `CarSelect::RefreshHeader` | `0x4B0140` | гараж; удобно для проверки денег |
| `CarDamage::SetDamageToZero` | `0x637D70` | ремонт; можно переигрывать состояние повреждений |
| `CarRenderInfo::Render` | `0x620AE0` | отрисовка машины; сюда вешать псевдо-машины |
| `CarRenderInfo::RenderNeon` | `0x60D7F0` | неон |
| `MenuScreen::SetButtons` | `0x54E6E0` | нижняя панель кнопок |
| `MenuScreen::ShowTwoButtons` | `0x558790` | диалоги |

Запуск:

```powershell
.\build\coop-probe.exe --exe "<game>\speed2.exe" --json probe-report.json
```

Код возврата `0` — все якоря на месте; `2` — сборка другая, таблицу надо снимать заново.

## Таблица `[Bindings]` в `nfsu2coop.ini`

| Ключ | Тип | Что |
|---|---|---|
| `CarPointer` | VA | адрес указателя на объект машины игрока |
| `PosOffset` | offset | `Vec3` позиции внутри объекта |
| `VelOffset` | offset | `Vec3` скорости |
| `YawOffset` | offset | `float` поворота |
| `SpeedOffset` | offset | `float` скорости вперёд (если есть) |
| `GearOffset` | offset | `u16` передачи |
| `TrafficList` | VA | адрес указателя на массив машин трафика |
| `TrafficCount` | VA | адрес `int` количества |
| `TrafficStride` | offset | размер элемента массива |
| `TrafficPosOffset` | offset | `Vec3` позиции в элементе |
| `TrafficModelOffset` | offset | `u8` модели |
| `StartEvent` | VA | `void __cdecl(int eventId)` — запуск карьерного события |
| `CareerCash` | VA | `void __cdecl(int cash)` |
| `CareerRep` | VA | `void __cdecl(int rep)` |
| `ZonePointer` | VA | `u32` текущей зоны |

Все нули = протокольный режим: сеть, гонки, зачёт, карьера, HUD — работают; машина и
трафик не читаются, в HUD висит предупреждение.

## Как найти значения (пошагово)

Нужны `x64dbg` (32-бит), `Cheat Engine` и/или `Ghidra`. Игра должна быть в гараже или
в свободной езде.

1. **Машина игрока.** В Cheat Engine ищите `float` скорости по спидометру, затем
   «pointer scan» до статической базы (зелёный адрес в модуле `speed2.exe`).
   Альтернатива в x64dbg: breakpoint на `Player::ClearZone` (`0x5FFE70`), `this` в
   `ecx`/стеке — это объект игрока; от него ищите поля позиции (рядом лежат скорость
   и поворот, значения меняются при движении).
2. Проверьте кандидата: `PosOffset` должен давать три `float`, которые меняются
   при движении и совпадают с координатами на миникарте.
3. **Трафик.** В Cheat Engine найдите количество машин (меняется при въезде в район),
   затем массив. В x64dbg удобно ловить `CarRenderInfo::Render` (`0x620AE0`) и смотреть,
   откуда приходит указатель на машину — рядом обычно массив.
4. **Старт события.** Breakpoint на `MenuScreen::BaseNotify` (`0x55B5C0`) при запуске
   гонки из меню; функция, которая получает `eventId`, — кандидат в `StartEvent`.
   Проверяйте на копии профиля, а не на основном сохранении.
5. **Деньги/репутация.** Найдите `int` денег, pointer scan до базы; функции записи
   обычно рядом с `BuyCarPart` (`0x5289F0`).

Каждый шаг записывайте в `local/` (не в git): адрес, чем проверили, на какой сборке.

## Проверка после заполнения

Запустите игру и посмотрите `scripts\NFSU2Coop.log`:

```
game: bindings car=0061A2C0 pos=1C traffic=0061B000
game: 10 anchors resolved
```

В HUD пропадает предупреждение, в строке статуса появляются `traffic N`, а на втором
клиенте — `puppets N` (чужие машины учитываются). Если позиция «прыгает» — неверный
`PosOffset` или читается не тот объект; если игра падает — адрес указывает в
невалидную память (мод проверяет `VirtualQuery`, но гонка с движком возможна).

## Безопасность

* Каждое чтение — через `VirtualQuery` (регион закоммичен, не `PAGE_NOACCESS/GUARD`,
  хватает длины). В MinGW нет SEH, поэтому это единственная защита.
* Запись и вызовы функций игры — только из очереди, исполняемой в потоке рендера
  (фактически главный поток игры), а не из сетевого потока.
* Мод ничего не патчит в `.exe`; все адреса — только чтение/вызовы.
