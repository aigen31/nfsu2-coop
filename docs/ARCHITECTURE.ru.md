# Архитектура

## Компоненты

```
                       ┌──────────────────────────── хост ────────────────────────────┐
                       │  NFSU2Coop.asi (Host)        coopd.exe (выделенный сервер)    │
   игра speed2.exe ───►│  ├ Nfsu2Game (чтение машины, трафик, вызовы игры)            │
                       │  ├ HostSession ◄── World ──► RaceDirector / ProgressLedger   │
                       │  ├ Link (ENet, UDP)                                          │
                       │  └ Overlay (ImGui/D3D9)                                      │
                       └───────────────┬──────────────────────────────────────────────┘
                                       │  UDP (2 канала: надёжный / ненадёжный)
                       ┌───────────────┴──────────────────────────────────────────────┐
                       │  NFSU2Coop.asi (Client)                                      │
                       │  ├ ClientSession ──► World (зеркало + своя машина)           │
                       │  ├ Nfsu2Game (своя машина; псевдо-машины чужих)              │
                       │  └ Overlay                                                   │
                       └──────────────────────────────────────────────────────────────┘
```

`src/core/` не знает ни о Windows, ни об игре: те же исходники собираются в тестовые
экзешники и в `.asi`. Всё, что касается движка, спрятано за `IGameWorld`.

## Кто чем владеет

| Состояние | Владелец | Как попадает к другим |
|---|---|---|
| Машина игрока (позиция, скорость, поворот, передача) | сам игрок | `PlayerState` 20 Гц, только хост принимает |
| Список игроков, слоты, имена | хост | `PlayerList` |
| Фаза гонки, отсчёт, зачёт, DNF | хост | `RaceCmd` (полный `RaceState`, надёжно) |
| Карьера (события, деньги, репутация) | хост | `ProgressEvent` → `ProgressSnapshot` |
| Городской трафик и AI-соперники | **движок хоста** | `Snapshot` чанками, `EntityRemove` |
| HUD, чат, уведомления | каждый | локально / `Chat` |

Клиент не «симулирует» чужие машины и не спавнит трафик: он рисует то, что прислал хост.
Поэтому класс багов «у двух игроков разный трафик» здесь невозможен по построению —
ценой того, что клиент не может взять на себя физику чужой машины (см. «Ограничения»).

## Почему трафик зеркалируется, а не симулируется всеми

В NFSU2 трафик и AI-соперников порождает движок конкретной машины: у них есть
собственные объекты, модели, маршруты и пул. Клиент не может «взять» чужую машину,
которой нет в его мире, без спавна нового объекта через внутренние функции игры.
Отсюда две стратегии:

1. **Детерминированная симуляция у всех** — требует одинакового PRNG и доступа к спавну;
   в закрытом движке это самый быстрый путь к рассинхрону.
2. **Единственный симулятор + зеркало** — хост читает свои машины и рассылает их
   состояние; клиент рисует псевдо-машины и прячет свои.

Выбрана вторая: она проверяема без привязок к глубинам движка и не даёт двойной
симуляции. В `World` такие машины помечены `EKind::Traffic` / `EKind::Bot`, владелец —
слот 0, эпоха не нужна, потому что публикует их ровно один процесс.

## Потоки

* **Игровой поток** (`tickThread`, 60 Гц): опрос ENet, чтение машины, снапшоты,
  горячие клавиши, сборка `HudState`.
* **Поток рендера** (EndScene игры): ImGui; здесь же выполняется очередь вызовов игры
  (`pumpGameThread`), чтобы не трогать память движка из чужого потока.
* Тесты — один поток с реальными сокетами и `sleepMs(3)`; виртуального времени нет
  специально, чтобы проверять настоящий ENet.

## Один тик хоста

1. `link.poll()` — соединения, отключения, пакеты.
2. `updateLocalCar()` — прочитать свою машину, обновить сущность слота 0.
3. `mirrorGameEntities()` (10 Гц) — новые handle → новые net-id; пропавшие → `EntityRemove`.
4. `dropStaleEntities()` — страховка на случай, если движок не сообщил о деспавне.
5. `driveRace()` — авто-старт лобби, `raceTick`, смена фазы → рассылка, применение итогов.
6. Снапшоты каждому клиенту (20 Гц), с обрезкой по дистанции 350 м.
7. Дайджест (2 с) и пинг (2 с).

## Устойчивость

* Надёжный канал ENet: ретрансмит, дедупликация, порядок — для лобби, гонки, карьеры.
* Ненадёжный последовательный: трансформы, где старое состояние бесполезно.
* Таймаут молчания 8 с на клиенте, 10 с на пире ENet; отключение в гонке = DNF.
* Дайджест+ремонт: расхождение гонки/карьеры чинится полным снапшотом, а не догадками.
* Ограничение чтения памяти: `VirtualQuery` перед каждым чтением (нет SEH в MinGW).

## Границы

Мод не трогает античит и официальные сервисы, не правит файлы сохранений и не
патчит `.exe`. Всё, что делает мод с игрой, — чтение памяти по таблице адресов и
вызовы игровых функций, которые игрок и так вызывает (старт события, начисление денег).
